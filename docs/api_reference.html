Overview

MLPipelineHolder is a straightforward framework for reproducible machine-learning experimentation in Jupyter notebooks. It helps you progressively turn mature parts of an exploratory workflow into stable pipeline stages, while keeping configurations, hyperparameters, and pipeline structure flexible and easy to change.

The package exposes its public API from the top-level mlpipelineholder package. Every name listed in the index is importable directly:

Import the public API
from mlpipelineholder import (
    PipelineHandler,
    ExecutionBlock,
    GateBlock,
    PipelineLogger,
    ExecutionError,
    PersistenceError,
    PipelineError,
    RegistrationError,
    ResolutionError,
    rename_args,
)

PipelineHandler

PipelineHandler

The central class that owns configuration, values, child pipelines, execution, save/load, and logging. Construct one per pipeline scope, then attach blocks and child pipelines.

add_block()

add_block(registration_name: str, execution_priority: float, forced: bool = False) -> ExecutionBlock | None

Registers a new execution block. Blocks run in ascending priority order; functions registered inside one block run in parallel and therefore cannot depend on each other's outputs.

Parameters
  • registration_name: unique public name used for lookup, path targeting, logs, and persistence.
  • execution_priority: numeric position in this pipeline. Priorities with the same integer part form an alternative group.
  • forced: replace a conflicting node when True; otherwise log a warning and return None.

Returns the new ExecutionBlock, an identical existing expression block during a forced re-registration, or None when non-strict registration is skipped. Invalid names and strict-mode conflicts raise RegistrationError.

add_child_pipeline()

add_child_pipeline(child_pipeline: PipelineHandler, execution_priority: float, registration_name: str | None = None, forced: bool = False) -> PipelineHandler | None

Attaches an existing PipelineHandler as an immediate child node. The child is relocated under this pipeline's project tree, inherits the root's strict and memory settings, and participates in parent visibility and execution ordering.

Parameters
  • child_pipeline: detached or re-attachable pipeline to place under this parent; a pipeline cannot attach itself.
  • execution_priority: numeric position of the child among this parent's blocks and child pipelines.
  • registration_name: optional replacement for the child's current public name before attachment.
  • forced: replace a conflicting registered node and detach the child from a previous parent when permitted.

Returns the attached child, or None when a non-forced duplicate is skipped.

Raises RegistrationError if the child's declared output names conflict with visible configuration fields or pipeline constants anywhere in the tree.

create_atom_child_pipeline()

create_atom_child_pipeline( child_name: str, execution_priority: float, target_function: Any, gate_config: str | None = None, expected_value: Any = True, default_config_value: Any = True, output_variable_names: str | list[str] | tuple[str, ...] | None = None, save_to_disk_lst: list[str] | tuple[str, ...] | set[str] | None = None, param_mapping_dct: dict[str, str | None] | None = None, kwargs_dct: dict[str, str] | None = None, args_lst: tuple[str, ...] | list[str] | None = None, allow_existing_root: bool = True, forced: bool = True, block_priority: float = 10.0, *, param_mapping: dict[str, str | None] | None = None, overridden_outputs: dict[str, tuple[str, str]] | None = None ) -> None

Builds and attaches a single-function child pipeline around target_function, wiring gate configuration, parameter mapping, positional and keyword arguments, and disk-backed outputs in one call.

Parameters
  • child_name: public name of the atom child.
  • execution_priority: position of the atom in the parent pipeline.
  • target_function: callable or import path executed by the atom.
  • gate_config: optional configuration field used as the atom's gate.
  • expected_value: value the gate must produce for the atom to run.
  • default_config_value: value created in the parent configuration for gate_config when that field is not already visible.
  • output_variable_names: zero, one, or multiple declared output names for the target function.
  • save_to_disk_lst: declared outputs that should be stored as artifacts.
  • param_mapping_dct: legacy parameter-to-pipeline-name mapping; cannot be combined with param_mapping.
  • kwargs_dct: keyword name to pipeline value mapping used to supply the target's **kwargs.
  • args_lst: ordered pipeline value names used to supply the target's *args.
  • allow_existing_root: allow reuse of an existing atom working directory when True.
  • forced: replace a conflicting atom definition; identical definitions remain a no-op.
  • block_priority: priority of the atom's internal implementation block.
  • param_mapping: preferred keyword-only parameter-to-pipeline-name mapping.
  • overridden_outputs: current output name to globally-upstream (pipeline_name, node_name) address.

The created atom child is immutable: after creation, adding blocks, child pipelines, functions, expressions, args/kwargs helpers, gates, or local configuration to it raises RegistrationError; constant values remain mutable.

An atom owns no configuration. Its config, get_config(), get_config_value(), get_full_config(), and execution-time argument resolution always use the current parent configuration. Call set_config(), set_configs(), update_config(), or update_configs() on the parent; calling any of these methods on the atom raises RegistrationError. Parent configuration changes are runtime state and do not replace an otherwise identical atom during re-registration.

If the target mutates a disk-backed input in place, that mutation is not persisted automatically. Declare the mutated name as an atom output (and include it in save_to_disk_lst when it should remain disk-backed), or return a new output value explicitly.

Re-calling create_atom_child_pipeline with an identical definition is a no-op that keeps the atom and every downstream output intact, even with forced=True. Identical means: same name, priority, gate (config field and expected value), and inner blocks (priorities, functions by identity, outputs, save_to_disk, mappings, args/kwargs helpers). Parent configuration values are not part of the atom definition. Any difference in the compared structural fields replaces the atom and always erases its own outputs. Normally it then invalidates from the earliest downstream block that consumes an affected output name; when cascade invalidation is forbidden, those other cached outputs are retained and may therefore be stale.

overridden_outputs={"output_name": ("pipeline_name", "node_name")} declares that this atom supersedes the same-named output of an existing globally-upstream block or atom. The pointer is installed only after this atom commits successfully.

Parameters

  • overrides: optional inputs used only for this run.

run_from()

run_from(*path_parts: str, overrides: dict[str, Any] | None = None) -> RunRecord

Executes the target node and everything after it. Outputs produced strictly before the target remain visible, the target may consume its own previous output, and outputs from later nodes are hidden until those nodes rerun. These rules apply recursively to nested paths such as run_from("modeling_pipeline", "predictor_training_pipeline"). Previous pointer-backed and disk-backed target inputs are materialized before invalidation, so nested restarts do not leave dangling pointers or delete an upstream artifact that the target still needs.

Parameters
  • path_parts: one immediate target name or a nested path ending at the block or child pipeline where rerunning starts.
  • overrides: optional inputs used only for this partial run.

run_block()

run_block(*path_parts: str, overrides: dict[str, Any] | None = None) -> RunRecord

Parameters
  • path_parts: one immediate target name or a nested path ending at the single node to execute.
  • overrides: optional inputs used only for this targeted run.

get_value()

get_value(variable_name: str) -> Any

Returns a produced value visible to this pipeline (own outputs, upstream parent outputs, or descendant values). If the value is disk-backed, the true object is loaded and returned.

Parameters
  • variable_name: visible produced-output name to resolve through provenance and any output-pointer chain.

get_node_output()

get_node_output(node_name: str, output_name: str) -> Any

Returns one materialized output from an immediate block or atom child. Output pointers are followed to the terminal owner and disk-backed values are loaded. Ordinary child-pipeline containers are rejected because their internal producers are not one immediate public output address.

Parameters
  • node_name: immediate block or atom-child name in this pipeline.
  • output_name: output declared and already produced by that node.

An atom with one internal producer returns that value directly; if multiple internal priorities produced the same name, the return value is a dict[float, Any] keyed by internal priority. Unknown nodes and missing outputs raise ResolutionError.

set_node_output()

set_node_output(node_name: str, output_name: str, value: Any, *, copy: bool = True, verbose: bool = False) -> None

Replaces an already-produced output of one named immediate block or atom child. Unlike set_value(), this method does not select the currently visible producer when several nodes produced the same output name; it changes only node_name's slot and then recomputes the visible winner by execution priority.

Parameters
  • node_name: immediate block or atom-child name in this pipeline.
  • output_name: output already produced by that node.
  • value: replacement object.
  • copy: deep-copy supported mutable values before assignment when True.
  • verbose: log copy or reference-fallback details.

For an atom, the replacement is written to its internal authoritative producer and synchronized through the parent tree. An atom with multiple internal producers for the same name is rejected as ambiguous. Ordinary child-pipeline containers, unknown immediate nodes, outputs that have not been produced, and output-pointer slots raise ResolutionError without changing state. Disk-backing is retained when the selected slot currently contains an artifact.

get_constant_value()

get_constant_value(variable_name: str) -> Any

Returns a pipeline constant set via set_constant_value(), resolving the nearest definition in the visibility chain: own constant, then earlier-priority sibling, then parent, then grandparent. Disk-backed values are loaded from disk.

Parameters
  • variable_name: constant name to resolve from the nearest visible owner.

Raises ResolutionError if no such constant exists.

set_constant_value()

set_constant_value(variable_name: str, value: Any, *, copy: bool = True, verbose: bool = False, to_disk: bool = False) -> None

Creates or replaces a pipeline constant. The constant is visible to this pipeline, its descendants, and downstream siblings through the parent visibility model.

Parameters
  • variable_name: public constant name; builtin names and output-conflicting names are rejected.
  • value: object to store.
  • copy: deep-copy supported mutable values before storage when True.
  • verbose: log when a mutable value is copied or falls back to reference storage.
  • to_disk: serialize the constant into the managed artifact tree instead of retaining it in memory.

Raises RegistrationError if the name is a declared output or an existing produced value anywhere in the pipeline tree, and for reserved builtin names.

By default mutable values (dict, list, NumPy arrays, pandas, Dask, PyTorch tensors/modules, dataclasses, ...) are stored as a deep copy so later in-place mutation outside the pipeline does not affect the constant. Pass copy=False to store by reference; values that cannot be deep-copied fall back to a reference with a warning. With verbose=True, an info line is logged when a mutable value is deeply copied. With to_disk=True the value is serialized to the artifact store instead of kept in memory (protected from in-place mutation; a non-serializable value raises PersistenceError); replacing a disk-backed constant deletes the previous artifact file.

Example
pipeline.set_constant_value("learning_rate", 0.01)
rate = pipeline.get_constant_value("learning_rate")
pipeline.set_constant_value("big_frame", frame, to_disk=True, verbose=True)

set_value()

set_value(variable_name: str, value: Any, *, copy: bool = True, verbose: bool = False) -> None

Updates an existing produced value, or injects a value for a declared-but-cleared produced name (a name declared as an output by a block that has not produced it yet). When several nodes produced the same name, the currently visible winning producer is updated; use set_node_output() to select a specific immediate block or atom.

Parameters
  • variable_name: existing or declared produced-output name to assign.
  • value: replacement object.
  • copy: deep-copy supported mutable values before assignment when True.
  • verbose: log copy or reference-fallback details.

Raises ResolutionError for unknown names and for names owned by pipeline constants (use set_constant_value() instead).

If the selected slot is an output pointer, set_value() raises ResolutionError without changing state. The message identifies the terminal pipeline.node.output that stores the real object and tells the caller which pipeline should receive set_value() instead.

Mutable values are stored as a deep copy by default (see set_constant_value()). Disk-backing is inherited from the producing block: if the deepest downstream block that produces the name registered it with save_to_disk, the value is saved to disk automatically, otherwise it stays in memory.

save_pipeline()

save_pipeline(path: str | Path | None = None, save_log_to_file: str | Path | None = None, *, verbose: bool = False, cleanup: str = "auto") -> Path

Saves the pipeline project tree. Without path, saves to the current project_root. Passing a different path creates a restart-safe copy of the current project tree (including nested children and disk-backed artifacts) before writing fresh state. The target must not overlap the current project tree.

Parameters
  • path: destination project root; None saves in place.
  • save_log_to_file: optional additional file receiving a copy of the current pipeline log.
  • verbose: expose advisory callable-reference and placeholder warnings that are suppressed by default.
  • cleanup: obsolete saved-object policy for in-place saves: "auto" deletes automatically, "confirm" prompts first, and "none" retains obsolete framework-generated artifacts and child trees.

Cleanup runs only after the new state payload commits and treats that payload as the liveness authority. Referenced artifacts are retained; inspection or deletion failures are logged without invalidating the successful save.

When a pipeline_backup_directory is configured, an in-place save also refreshes the backup copy.

Every call also archives a timestamped copy of the current pipeline.log into history_logs/ inside the project root (e.g. history_logs/2026-08-18_16-38-14.857.log, UTC, yyyy-mm-dd_hh-mm-ss.mmm), preserving the save-time log snapshot even though loading a pipeline starts a fresh pipeline.log.

When a pipeline_backup_directory is configured, the refreshed backup copy also receives the updated history_logs/ folder. Loading a saved project restores its history_logs/ folder into the project root, so previously archived snapshots remain available after a load.

With verbose=False (the default) the advisory warnings emitted during saving are suppressed: the callable-reference notice and per-value placeholder warnings for unserialisable or non-importable values. Pass verbose=True to show them. Warnings unrelated to saving (registration, load, logger) are never suppressed.

load_pipeline()

@classmethod load_pipeline(path: str | Path, *, forced_deleting: bool = False, verbose: bool = False, auto_resolve_placeholders: bool = True) -> PipelineHandler

Loads a saved pipeline project. The state payload, placeholders, and callable references are fully reconstructed in a temporary preflight first. Only after that succeeds may a non-canonical saved tree replace the canonical working directory; a preflight failure raises PersistenceError and leaves the existing working tree untouched.

Parameters
  • path: saved project root containing the pipeline payload and metadata.
  • forced_deleting=False asks for keyboard confirmation before deleting a non-empty canonical working directory.
  • forced_deleting=True deletes the canonical working directory directly.
  • verbose=True logs a warning when a pipeline constant was saved as a placeholder (e.g. an unserialisable value) and could not be restored; silent by default.
  • auto_resolve_placeholders=True (the default) re-runs producing blocks to recover produced values that were saved as placeholders. Exactly one block is executed per placeholder recovery, in upstream-to-downstream order, and fresh values are injected without invalidating downstream outputs. Each recovery appends a RunRecord labelled auto_resolve_placeholder:<block>. With verbose=True, outputs that stay unrecoverable log the reason (unresolvable input, placeholder constant input, input only produced by a gate-off block, or no registered producing block); a block that raises during re-execution always logs an unrecoverable warning. Gate-off pipelines are skipped silently. Pass False to keep legacy placeholder behaviour: saved placeholders raise ResolutionError when read.
  • Pure-dataclass values (config objects, constants, and produced values) that could not be pickled are saved as structured references and reconstructed at load regardless of auto_resolve_placeholders: a real dataclass instance when the class is importable and reconstructible from the saved fields, including dataclasses with non-init fields; a SimpleNamespace fallback is used otherwise (verbose-gated warning).

Missing runtime callables raise during loading instead of being passed to stages as inert placeholders. Values saved as RuntimeValueReference placeholders raise ResolutionError when read via get_value, get_constant_value, or get_config_value, and when resolved as a function argument.

recover_variable_from_backup()

recover_variable_from_backup(name: str, *, pipeline_name: str | None = None) -> None

Restores one current value from the latest complete in-place backup. Call on the root pipeline only. Updates in place and returns None.

Parameters

register_function()

register_function( function_or_path: Any, output_variable_names: str | list[str] | tuple[str, ...] | None, save_to_disk: list[str] | tuple[str, ...] | set[str] | None = None, param_mapping: dict[str, str | None] | None = None, var_pos_name: str | None = None, var_kw_name: str | None = None, forced: bool = False, overridden_outputs: dict[str, tuple[str, str]] | None = None ) -> FunctionRegistration | None

Registers a function in this block. Inputs are resolved at execution time from explicit overrides, para_value_dict, config fields, and function defaults, in that order.

Parameters
  • function_or_path: callable or import path to register.
  • output_variable_names: zero, one, or multiple names matched to the callable's return value.
  • save_to_disk: declared outputs serialized into the managed artifact tree.
  • param_mapping: callable parameter name to pipeline-facing value name, or literal None.
  • var_pos_name: block args-helper name supplying the callable's *args.
  • var_kw_name: block kwargs-helper name supplying the callable's **kwargs.
  • forced: replace the same registered function name when the definition differs.
  • overridden_outputs: current output name to globally-upstream (pipeline_name, node_name) address.
  • Returns the created FunctionRegistration, or None when the registration was rejected (for example duplicate output names, output names conflicting with visible configuration fields or pipeline constants, or builtin names).
  • param_mapping exposes safer pipeline-facing parameter names without changing the callable.
  • var_pos_name / var_kw_name map variadic *args / **kwargs to named pipeline inputs.
  • save_to_disk names must be a subset of output_variable_names.
  • overridden_outputs maps a current output name to an existing upstream (pipeline_name, node_name) that declares the same output.
  • With forced=True, replacing a function with an identical registration (same callable identity — import path or runtime object — and same outputs, save_to_disk, mappings, and bound args/kwargs helper snapshots) is a no-op that leaves all outputs untouched. Any real difference erases the function's own outputs, then invalidates from the earliest downstream block that consumes any affected output name — the same unified rule used by register_expression and create_atom_child_pipeline; unrelated downstream blocks are preserved. A redefined notebook-local function is a different object and is therefore treated as a real change.
  • functools.partial registrations are compared structurally by wrapped callable identity and bound args/keywords. Saving rejects a partial whose bound values would become unresolved placeholders; runtime-only bound callables must remain available under their saved __main__ names when loading.
Example

    multiply,
    ["result"],
    param_mapping={"seed": "seed", "factor": "factor"},
)
block.register_function(
    mapped_variadic,
    ["result"],
    param_mapping={"obj": "payload", "scale": "scale_value"},
    var_pos_name="extra_args",
    var_kw_name="extra_kwargs",
)

register_expression()

register_expression( code: str, *, output_variable_name: str | None = None, save_to_disk: bool = False, forced: bool = False, warn_on_input_mutation: bool = False, overridden_outputs: dict[str, tuple[str, str]] | None = None ) -> ExpressionRegistration | None

Registers a single-statement expression. Must be an assignment (NAME = EXPR) or a print/logger call. No semicolons, imports, eval/exec/__import__, comprehensions, walrus operators, or nested definitions.

Parameters
  • code: one supported assignment or print/logger expression.
  • output_variable_name: optional explicit assignment output name; normally inferred from code.
  • save_to_disk: persist the expression output as an artifact when True.
  • forced: replace the block's existing expression when the definition differs.
  • warn_on_input_mutation: warn when evaluation appears to mutate an input object in place.
  • overridden_outputs: expression output name to globally-upstream (pipeline_name, node_name) address.
  • Returns None when the registration is rejected (for example output name conflicts).
  • Imports used by expressions are supplied through define_expression_runtime().
  • overridden_outputs uses the same upstream-address contract as function and atom registrations.
  • A block holds at most one expression: a second assignment, a second logging expression, or a mixed pair raises RegistrationError; re-registering the existing expression with forced=True replaces it.
  • Forced replacement follows the same unified rule as register_function and create_atom_child_pipeline: an identical re-registration is a no-op that preserves all outputs; any real change erases the expression's own output, then invalidates from the earliest downstream block that consumes any affected output name (old outputs plus new outputs colliding with downstream inputs), warning about the consumers. Unrelated downstream blocks and consumers shielded by a later same-name producer are left untouched.

Persisted output pointers

Expression blocks, function blocks, and atom pipelines may replace a same-named upstream output with a pointer to their own committed output. Addresses use globally unique pipeline names and immediate public node names; ordinary pipeline containers, atom implementation blocks, constants, configuration fields, missing outputs, detached roots, and downstream targets are rejected. Nodes in the same integer priority group are alternatives rather than strictly ordered stages, so they cannot point to each other.

Public reads and function/expression inputs follow the chain recursively and return the terminal object or loaded disk artifact, never the pointer. A chain such as A → B → C therefore retains the real completed value at C while A and B contain small pointers, reducing retained memory and duplicate disk generations during complete experimental runs.

Invalidation splices surviving links around removed intermediate pointers, then promotes a removed terminal value to the latest surviving upstream pointer slot without copying the in-memory object. Disk-backed promotion moves the managed artifact to the surviving owner. forbid_invalidate_objects() additionally preserves unrelated cached outputs instead of cascading through them. A partial rerun can temporarily represent more than one generation; rerunning the complete missing suffix converges the chain again. Failed pointer commits restore the prior pointer graph and delete any newly produced disk artifact.

Pointer declarations and active runtime links are preserved by save_pipeline() and load_pipeline(). Missing destinations and cycles are rejected during loading.
