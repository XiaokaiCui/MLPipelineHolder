Overview

Build a pipeline →Configuration, blocks, and child pipelines. Inspect an experiment →Resolve inputs, copy values, and investigate. Save & restore →Persistence, backups, and recovery.

MLPipelineHolder is a straightforward framework for reproducible machine-learning experimentation in Jupyter notebooks. It helps you progressively turn mature parts of an exploratory workflow into stable pipeline stages, while keeping configurations, hyperparameters, and pipeline structure flexible and easy to change.

The package exposes its public API from the top-level mlpipelineholder package. Every top-level class and function shown below is importable directly. Additional record types in Data models are imported from mlpipelineholder.core.models:

Import the public API
from mlpipelineholder import (
    PipelineHolder,
    AtomPipeline,
    ExecutionBlock,
    GateBlock,
    PipelineLogger,
    ExecutionError,
    InspectionCopyError,
    InspectionMemoryError,
    PersistenceError,
    PipelineError,
    RegistrationError,
    ResolutionSource,
    ResolvedInspectionCall,
    ResolutionError,
    pipeline_resolving,
    rename_args,
)

PipelineHolder is the canonical class name. PipelineHandler remains available as an alias of the same class, so notebooks written before the rename keep working unchanged.

The implementation is organised into subpackages (core, execution, state, persistence, integrations, presentation). Only the top-level package names are public API. As of 0.3.10 the legacy flat module imports (for example mlpipelineholder.models) were intentionally removed - import from the subpackage paths documented here instead. Pipelines saved by earlier releases still load: historical flat module names are mapped to their current homes while unpickling, so no manual migration is needed.

PipelineHolder

PipelineHolder

The central class that owns configuration, values, child pipelines, execution, save/load, and logging. Construct one per pipeline scope, then attach blocks and child pipelines. PipelineHandler is an alias of this class.

save_to_storage()

save_to_storage(object_name: str, object_value: Any, object_description: str | None = None) -> str

Adds an arbitrary object to the root-owned storage registry and returns its generated hexadecimal hash ID. Ordinary values remain in memory until save_pipeline() persists them. An Optuna Study is persisted eagerly as an independent copy: its exact incoming name receives the next free appended suffix across the shared database, so abc becomes abc_1 while abc_1 becomes abc_1_1. Stored objects are never exposed to registered pipeline arguments or execution, even when a stored name matches a configuration field, constant, or output. Root-level temporary investigation APIs may use storage as their final fallback.

Parameters
  • object_name: non-empty display name for the record.
  • object_value: object to store; a supported serializer is selected automatically.
  • object_description: optional descriptive text.
Returns

The record’s hash ID as a str, which can be used to retrieve, update, or remove it.

Example
hash_id = pipeline.save_to_storage("settings", {"window": 20})
print(hash_id)

Returns

None. Updates the selected record in place, retaining its hash ID.

All five storage methods are root-only. Calling one on any attached child or atom raises RegistrationError. Attaching a standalone pipeline merges its storage into the ultimate root. A root record wins any hash collision and the child's colliding artifact is deleted. Values with no dedicated serializer fall back to pickle with a warning; values that pickle cannot serialize remain usable in memory but are omitted from saved state with a warning.

Inspection & copying

inspect()

inspect(*names: str, compute: bool = False, priority: int | None = None) -> PipelineInspection

Returns a one-shot context manager that resolves several values for temporary interactive investigation without registering a node or changing pipeline state. Values resolve when the with block starts through the same source-of-truth rules used by pipeline_resolving(): visible produced outputs, pipeline constants, visible configuration, and finally uncached object storage for a root pipeline. Retrieval failures propagate without falling through to a lower-priority source.

When a value is served from copy_for_inspection(), an info log names the value and the priority it was copied with, and reminds the caller to reuse that priority if original objects must be preserved. When a value was not copied, an info log recommends copying it, and disk-backed values additionally note that repeated disk loading is inefficient. Objects that could not be copied at all are only announced by the warning emitted at copy time.

  • names: one or more unique, non-empty pipeline-facing names.
  • compute: boolean only. When True, compute resolved Dask DataFrame and Series values before exposing them.
  • priority: optional integer execution group used to select an investigation node at or below that group before resolving produced outputs.

Priority-based value inspection selects a node for investigation; it does not guarantee that a normal pipeline run will execute that same node. In particular, if evaluating a child-pipeline gate fails during selection, the selector retains its intentional fail-open behaviour and may select that child. inspect_node(priority=...) is different: it selects one immediate block or atom by its exact finite numeric priority and does not perform priority-group fallback.

Inside the block, valid non-conflicting names support attribute access such as data.selected_df. Dictionary access such as data["selected_df"] works for every requested name and is required for names that are not valid Python attributes or that conflict with context-object attributes. On exit, the context clears its value references and pipeline reference. Access after exit and context reuse raise RuntimeError; values assigned to another variable by user code remain available normally.

This value-context form is available on root and ordinary child pipelines. AtomPipeline.inspect() and ExecutionBlock.inspect() intentionally use the same method name for non-committing inspection of a registered function or expression instead.

Returns

A one-shot PipelineInspection context manager. Inside with ... as ctx, read each requested value using ctx.name or ctx["name"]. Exiting releases the context’s references and disables further access.

copy_for_inspection()

copy_for_inspection(object_names: list[str] | tuple[str, ...], *, compute: bool = True, priority: int | None = None) -> None

Copies selected investigation values into a transient in-memory cache used by PipelineHolder.inspect(), pipeline_resolving(), PipelineHolder.inspect_node(), ExecutionBlock.inspect(), and AtomPipeline.inspect(). Every inspection path checks this cache first and falls back to its normal resolution when a name was not copied. Cached values are already isolated copies, so block/atom inspection never copies them again regardless of allow_mutable_objects. Names follow the same output, constant, configuration, and root-object-storage precedence as those investigation APIs. priority accepts the same integer priority group as inspect(priority=...) and resolves the same priority-scoped view, so preloaded values are recognized by matching-priority inspections. Every name in one call is resolved before anything is copied.

Disk-backed values are loaded once and cached. In-memory values are isolated with the same copying semantics as protected allow_mutable_objects=False block inspection, so pandas object-dtype cells, NumPy object arrays, Torch tensors, and Dask collections are copied consistently; when isolation is impossible, the method round-trips the value through the normal artifact serializers in a temporary folder under the project root, deleting that folder afterwards; save_pipeline() also sweeps leftover temporary folders across the pipeline and its attached children. Custom objects are reconstructed by following their own copy/reduce protocol, the same protocol Python's deepcopy and pickle use, with constructor arguments, state, and container items copied through this copier, so nested pandas object-dtype cells, NumPy object arrays, and structured object fields are isolated consistently and shared sub-objects keep their aliases as in protected block inspection. Exactly typed built-in containers, immutable leaves, and pandas, NumPy, Dask, and Torch values take specialized paths; slotted and private-slot state, custom __new__/__getnewargs__, and user __getstate__/__setstate__ are honored, while classes that define their own __deepcopy__ keep that implementation and own its isolation semantics. A temporary serializer round-trip can isolate a value but may not preserve aliases to separately copied values. Objects that cannot be isolated at all are skipped with a logger warning that they will be inspected by reference and recommending save_pipeline() before inspection plus a reload from backup afterwards. Optuna studies and samplers, placeholders, callable references, and Torch state artifacts are rejected. Cached cache-priority, compute, and object identity are remembered.

Copying is incremental: names omitted from a later call remain cached, while every named object is re-resolved with the requested priority and re-copied. A later compute setting replaces the earlier setting for those names; the default compute=True computes Dask DataFrame and Series values before caching, while False keeps the lazy collection. Cached objects are shared, so investigation-time mutations remain visible until the object is copied again, all objects are refreshed, or the cache is unloaded. For in-memory values that cannot be weak-referenced (lists, dictionaries, and similar), the cache keeps the copied original alive next to the isolated copy so a replaced value can never be served from a reused object address; that guard is released as soon as a lookup detects the replacement, or when the entry is refreshed or unloaded. Investigation calls log at info level when a value is served from this cache, and when a value is not copied they recommend copying it; disk-backed misses also note that repeated loading is inefficient. The legacy name load_for_inspection() remains a silent alias of this method.

The method logs the signed net process-RSS change measured after post-copy cleanup, together with an estimated newly cached size, and logs a reminder to call unload_inspection_objects() between pipeline or block executions or refresh_copied_objects() to reload every copied object, because cached values may become stale. Cleanup before the sample and before the baseline collects garbage, attempts to return free allocator arenas where the platform supports it, and releases PyArrow's pool, whose freed buffers are invisible to standard allocator trimming. This keeps the single reported number close to the retained cache growth instead of the copying peak; it is best-effort, so RSS remains process-wide and can still differ from the cached size or turn negative. The retained-size estimate uses metadata such as DataFrame memory usage, immutable object sizes, array byte counts, and tensor element sizes; exact array/tensor storage windows are deduplicated, bounded sampling is prefixed with “at least”, and CUDA storage is reported separately by device because host RSS does not include VRAM. Normal pipeline execution and ordinary value getters never use this cache.

Parameters
  • object_names: list or tuple of visible names to copy into the inspection cache.
  • compute: compute Dask values before copying; defaults to True.
  • priority: optional integer group used to resolve and bind the copied names.
Returns

None. Populates the inspection cache; later inspection reads reuse its copies.

Example
pipeline.copy_for_inspection(["seed"], priority=1)
with pipeline.inspect("seed", priority=1) as ctx:
    print(ctx.seed)

refresh_copied_objects()

refresh_copied_objects() -> None

Re-resolves and re-copies every object currently held in this pipeline's inspection cache using each name's most recent priority and compute settings; copied in-memory values are always re-copied from the current original, discarding cached mutations. Refreshing is transactional: if any name can no longer be resolved, copied, or loaded, an exception is raised and existing cached values remain unchanged. Calling it with an empty cache emits UserWarning. The legacy name refresh_loaded_objects() remains a silent alias of this method.

Parameters

None.

Returns

None. Refreshes existing inspection-cache bindings from their recorded sources.

Example
pipeline.copy_for_inspection(["seed"])
pipeline.refresh_copied_objects()

unload_inspection_objects()

unload_inspection_objects() -> None

Removes every object copied through copy_for_inspection() on this pipeline instance, performs garbage collection and best-effort allocator trimming, and logs the net process-RSS change measured after cleanup together with the estimated size of the removed cached objects. It does not remove disk artifacts or affect another attached pipeline's independent inspection cache. The cleanup also attempts to release PyArrow's pool before the final sample. If a weak-referenceable cached copy remains alive after the cache is cleared, the method warns with its object name: another reference, such as a notebook variable or inspection result, may still retain its memory. This check cannot identify the specific variable or detect external references to non-weak-referenceable values and shared backing buffers. Process-wide RSS can also increase because of unrelated allocations, and the host RSS figure does not measure VRAM. Calling it with an empty cache emits UserWarning.

create_atom_child_pipeline()

create_atom_child_pipeline( child_name: str, execution_priority: float, target_function: Any, gate_config: str | None = None, expected_value: Any = True, output_variable_names: str | list[str] | tuple[str, ...] | None = None, save_to_disk_lst: list[str] | tuple[str, ...] | set[str] | None = None, param_mapping_dct: dict[str, str | None] | None = None, kwargs_dct: dict[str, str] | None = None, args_lst: tuple[str, ...] | list[str] | None = None, forced: bool = True, block_priority: float = 10.0, *, param_mapping: dict[str, str | None] | None = None, overridden_outputs: dict[str, tuple[str, str]] | None = None ) -> None

Builds and attaches a single-function child pipeline around target_function, wiring gate configuration, parameter mapping, positional and keyword arguments, and disk-backed outputs in one call.

Parameters

  • overridden_outputs: current output name to globally-upstream (pipeline_name, node_name) address.

The created atom child is immutable: after creation, adding blocks, child pipelines, functions, expressions, args/kwargs helpers, gates, or local configuration to it raises RegistrationError; constant values remain mutable. Atom creation always reuses its framework-managed child directory and never prompts for or controls directory cleanup. See AtomPipeline for the complete list of sealed operations and the full class description.

An atom owns no configuration. Its config, get_config(), get_config_value(), get_full_config(), and execution-time argument resolution always use the current parent configuration. Call set_config(), set_configs(), update_config(), or update_configs() on the parent; calling any of these methods on the atom raises RegistrationError. Parent configuration changes are runtime state and do not replace an otherwise identical atom during re-registration.

In strict mode, atom function arguments resolve only from param_mapping/param_mapping_dct, args_lst, kwargs_dct, the callable's own defaults, and the automatic pipeline logger injection. A same-named visible config, output, constant, or runtime override is not consumed unless it was explicitly mapped.

If the target mutates a disk-backed input in place, that mutation is not persisted automatically. Declare the mutated name as an atom output (and include it in save_to_disk_lst when it should remain disk-backed), or return a new output value explicitly.

The reserved output marker "_" discards the returned value at that position. It still counts when validating the callable's return annotation and returned tuple/list length, but it is never declared, made visible, persisted, or included in run results. Repeated markers are allowed, for example ["_", "o2e_root", "_", "bce"], and ["_"] discards a single return value. Including "_" in save_to_disk_lst raises RegistrationError.

If the target function cannot be registered, atom creation raises RegistrationError instead of attaching an atom without an executable function. An existing atom with the same name and its outputs remain unchanged.

Re-calling create_atom_child_pipeline with an identical definition is a no-op that keeps the atom and every downstream output intact, even with forced=True. Identical means: same name, priority, gate (config field and expected value), and inner blocks (priorities, functions by identity, outputs, save_to_disk, mappings, args/kwargs helpers). Parent configuration values are not part of the atom definition. Any difference in the compared structural fields replaces the atom and always erases its own outputs. Normally it then invalidates from the earliest downstream block that consumes an affected output name; when cascade invalidation is forbidden, those other cached outputs are retained and may therefore be stale.

overridden_outputs={"output_name": ("pipeline_name", "node_name")} declares that this atom supersedes the same-named output of an existing globally-upstream block or atom. The pointer is installed only after this atom commits successfully.

Returns

None. Creates or replaces a sealed atom; retrieve it with get_child_pipeline(child_name). Both execution_priority and block_priority must be finite, non-negative real numbers (not bool), validated before directories are created.

    return seed * 2

    param_mapping={"seed": "seed"},

AtomPipeline

AtomPipeline

An immutable, block-like child pipeline. You never create one directly: call create_atom_child_pipeline() on the parent pipeline, and the framework builds a sealed AtomPipeline that wraps one target function and an optional gate.

class mlpipelineholder.AtomPipeline

An atom participates in its parent's execution exactly like a block: the parent runs it as one indivisible node, its outputs appear under one public node name, and an optional gate can skip it. Internally the atom holds one implementation block that calls the target function; that structure is fixed when the atom is created.

AtomPipeline inherits the full PipelineHolder reading surface, so every method documented for PipelineHolder is available on an atom unless it is listed as rejected below.

What still works after creation
  • Reading state: get_value(), get_node_output(), get_selected_node_output(), get_config(), get_full_config(), config_as_dict(), list_visible_*(), has_visible_*(), list_declared_outputs(), describe_pipeline(), full_path(), qualified_node_name(), and the other read-only helpers.
  • Running: the parent's run_all(), run_until(), run_from(), and run_block() execute the atom as part of the parent's node list.
  • Execution inspection: atom.inspect() resolves or invokes its target registration without committing outputs and without evaluating the atom gate.
  • Configuration through the parent: atom.config, atom.get_config_value(), and execution-time argument resolution always use the parent's current configuration.
  • Parent value changes: set_constant_value(), set_value(), set_node_output(), and update_value() keep working (values and constants stay mutable).
What raises RegistrationError after creation
  • Growing or shrinking the atom: add_block(), add_child_pipeline(), create_atom_child_pipeline(), and remove_block().
  • Changing the gate: add_gate_block(), set_gate_block(), and reset_gate_block(). The gate is fixed when the atom is created.
  • Changing configuration: set_config(), set_configs(), update_config(), and update_configs(). Atoms own no configuration.
  • Mutating the atom's internal block: registering or removing functions, expressions, args, or kwargs helpers.
Creating and re-creating atoms

All creation arguments (name, priority, target function, optional gate, declared outputs, disk-backed outputs, parameter mappings, args/kwargs helpers, and output overrides) are documented on create_atom_child_pipeline(). Calling it again with an identical definition is a no-op that keeps the atom and every downstream output intact, even with forced=True; any real difference replaces the atom and erases its own outputs.

Save and load

Atoms are saved and loaded together with their parent. A loaded atom arrives already sealed, and re-registering an identical definition after a load remains a no-op.

inspect()

inspect(function_name: str | None = None, overrides: dict[str, Any] | None = None, strict_mode: bool | None = None, resolve_only: bool = False, allow_mutable_objects: bool = True, memory_safety_margin: float = 0.25) -> Any | ResolvedInspectionCall

Resolves and optionally invokes one registered function or expression using the same visible inputs as a targeted block run, including previous committed outputs from this node. It returns the callable's raw Python result, ignoring declared output slots; an assignment expression returns its assigned value, while a print-only expression returns None. Inspection does not commit outputs, write declared artifacts, add run history, invalidate downstream state, or update output pointers.

Inspection selects one registration, not the whole block. Other functions registered at the same priority are not run, so inspecting one registration is not equivalent to concurrently executing a multi-function block. Same-block dependency validation still applies, except that an original-parameter-name override fully replaces that parameter's dependency and removes it from the check.

Parameters
  • function_name: required when the block has multiple registrations. Duplicate legacy registrations are accepted only when they reference the same callable object and their effective input bindings are equivalent after inspection overrides.
  • overrides: temporary values keyed by original callable parameter name, including variadic parameter names and logger. Unknown names raise ResolutionError. Overrides have highest precedence and are passed through by identity in both mutability modes.
  • strict_mode: temporary resolution mode. None follows the root pipeline. Expressions resolve the same way in either mode.
  • resolve_only: return a ResolvedInspectionCall containing the exact args, kwargs, signature-bound arguments, and structured sources, without invoking user code. When protected mode is selected, the memory preflight runs before constructing protected copies, so resolve_only=True follows the same rules.
  • allow_mutable_objects: defaults to True. Pipeline-owned mutable values and mutable callable defaults are passed to the inspected callable by reference, so inspected code may mutate them. Set this to False for protected mode, which copies mutable pipeline-owned values (and mutable callable defaults) with one shared memo so ordinary object aliases and cycles are preserved.
  • memory_safety_margin: protected mode only. Fraction added to the estimated additional memory before comparing it with measured available memory. The default 0.25 requires 25% headroom. Must be a finite non-negative number.

Shared default: inspection functions and expressions receive original pipeline objects by reference by default. In-place mutations may change the pipeline's existing values even though inspection does not commit returned outputs, invalidate nodes, or persist artifacts. This includes pandas DataFrames, NumPy arrays, nested mutable containers, model objects, and other mutable inputs.

Protected mode: allow_mutable_objects=False copies mutable pipeline values and callable defaults, with specialized handling for pandas, NumPy, Dask, and Torch values. Exactly typed built-in containers and library values take those specialized paths, while other objects are reconstructed through their own copy/reduce protocol with every component copied by the same logic, so nested pandas values and slotted state stay isolated; classes with their own __deepcopy__ keep that implementation, and reconstruction failures raise InspectionCopyError. Exact Python functions, built-in functions and methods without a live instance owner, and the pipeline's real logger retain identity, while bound methods, bound built-in methods, and method wrappers are copied through their owner so mutations cannot reach the original. Shared-state objects that cannot be isolated, including Optuna studies and samplers, raise InspectionCopyError before a known disk-backed Optuna artifact is loaded; provide an override or explicitly opt into shared mutable objects. Copying large values such as pandas DataFrames can be slow and can temporarily double their memory footprint. Copying a Dask collection copies only the lazy graph object; it does not compute the dataset and does not sandbox graph execution or the external data sources and side effects the graph reads or triggers. Distinct NumPy views or Torch tensors that share storage may become independent protected copies, so their copied view relationship can differ from normal execution; mutating a protected copy must still leave the original pipeline-owned storage unchanged.

Memory preflight (best effort): before protected copying, inspection performs a lightweight estimate of materialization, copy, and temporary allocations. Numeric arrays and tabular values use storage metadata; object-dtype values and basic containers use bounded shallow samples instead of full cell or object-graph traversal. Shared already-materialized identities are counted once, while separate artifact loads are counted separately. The estimate plus memory_safety_margin is compared with inexpensive measurements of system RAM, container/process limits, and CUDA device memory where applicable. Measurements may be incomplete, compressed artifacts can expand unpredictably, and a Dask parquet loader may fall back from lazy Dask loading to eager pandas loading. When the estimate appears excessive, is materially uncertain, or available memory cannot be measured, an interactive terminal or Jupyter/IPython session displays the reason and asks whether to continue. Only an explicit Yes proceeds; declining or running without usable interactive input raises InspectionMemoryError before protected copying or artifact loading starts. This is advisory, not an OOM guarantee: another process can consume memory after preflight, a user-approved copy can still fail, and an operating-system OOM kill can terminate Python or Jupyter and lose unsaved in-memory work. Shared default mode does not run this estimation pass.

Not a sandbox: non-committing describes framework-managed state only. User code may still perform arbitrary external side effects, mutate an explicitly supplied override, mutate pipeline-owned objects in shared default mode, write logs through the real logger, or print into the normal captured pipeline log. Protected copying isolates pipeline-owned mutable values but does not isolate external side effects performed by arbitrary user code. Invocation failures are wrapped in ExecutionError with the original exception retained as __cause__.

Returns

The callable’s raw Python result, ignoring declared output slots; a ResolvedInspectionCall when resolve_only=True. Nothing is committed to the pipeline.

Inspect with shared inputs by default

    function_name="build_features",
    overrides={"limit": 100},
    resolve_only=True,
)
print(resolved.arguments)

register_function()

register_function( function_or_path: Any, output_variable_names: str | list[str] | tuple[str, ...] | None, save_to_disk: list[str] | tuple[str, ...] | set[str] | None = None, param_mapping: dict[str, str | None] | None = None, var_pos_name: str | None = None, var_kw_name: str | None = None, forced: bool = False, overridden_outputs: dict[str, tuple[str, str]] | None = None ) -> FunctionRegistration | None

Registers a function in this block. Inputs are resolved at execution time from explicit overrides, para_value_dict, config fields, and function defaults, in that order.

Parameters
  • function_or_path: callable or import path to register.
  • output_variable_names: zero, one, or multiple positional slots matched to the callable's return value. Use "_" to ignore a slot.
  • save_to_disk: declared outputs serialized into the managed artifact tree.
  • param_mapping: callable parameter name to pipeline-facing value name, or literal None.
  • var_pos_name: optional block args-helper alias supplying the callable's *args. When omitted, a helper registered under the variadic parameter's own name is used consistently.
  • var_kw_name: optional block kwargs-helper alias supplying the callable's **kwargs. When omitted, a helper registered under the variadic parameter's own name is used consistently.
  • forced: replace the same registered function name when the definition differs.
  • overridden_outputs: current output name to globally-upstream (pipeline_name, node_name) address.
  • param_mapping exposes safer pipeline-facing parameter names without changing the callable.
  • var_pos_name / var_kw_name map variadic *args / **kwargs to named pipeline inputs.
  • save_to_disk names must be a subset of output_variable_names.
  • The reserved marker "_" still counts toward return annotation and runtime arity but is discarded instead of becoming a declared or produced output. Repeated markers are allowed. Including "_" in save_to_disk raises RegistrationError.
  • When global Arrow schema inference fails for a disk-backed Dask DataFrame, persistence warns and retries with schema=None. Each partition then infers its own Parquet schema, so partition schemas must remain compatible.
  • Artifact loading inspects Parquet metadata before reading. If pandas cannot parse a nested or third-party Arrow extension declaration such as list<item: double>[pyarrow], the unreadable declaration is neutralized in the in-memory Arrow schema before conversion. PyArrow then performs its normal metadata-driven pandas reconstruction globally, covering current and future supported column and index dtypes without type-specific conversion code; unreadable Arrow-backed fields retain their physical Arrow dtype. Directory artifacts normally remain lazy Dask DataFrames and projected reads use the same safe partition loader, but backend failures can trigger an eager pandas fallback.
  • overridden_outputs maps a current output name to an existing upstream (pipeline_name, node_name) that declares the same output.
  • With forced=True, replacing a function with an identical registration (same callable identity, outputs, save_to_disk, mappings, and bound args/kwargs helper snapshots) is a no-op that leaves all outputs untouched. Imported functions require both the same import path and the same callable object, so importlib.reload() always causes replacement even when the path or source appears unchanged. An unchanged re-executed __main__ notebook definition may remain a no-op when its executable definition and defaults match. Any real difference always erases the function's own outputs and normally invalidates from the earliest downstream consumer; after forbid_invalidate_objects(), downstream cached outputs are retained and may be stale. Unrelated downstream blocks are preserved.
  • functools.partial registrations are compared structurally by wrapped callable identity and bound args/keywords. Saving rejects a partial whose bound values would become unresolved placeholders; runtime-only bound callables must remain available under their saved __main__ names when loading.
Returns

The created FunctionRegistration, or None when the registration is rejected, for example duplicate output names, output names conflicting with visible configuration fields or pipeline constants, or builtin names.

  • output_variable_name: optional explicit assignment output name; normally inferred from code.
  • save_to_disk: persist the expression output as an artifact when True.
  • forced: replace the block's existing expression by default when the definition differs; pass False to reject a duplicate.
  • warn_on_input_mutation: warn when evaluation appears to mutate an input object in place.
  • overridden_outputs: expression output name to globally-upstream (pipeline_name, node_name) address.
  • Returns None when the registration is rejected (for example output name conflicts).
  • Imports used by expressions are supplied through define_expression_runtime().
  • overridden_outputs uses the same upstream-address contract as function and atom registrations.
  • A block holds at most one expression: a second assignment, logging expression, or mixed pair replaces the existing expression by default. Pass forced=False to raise RegistrationError instead.
  • Forced replacement follows the same unified rule as register_function and create_atom_child_pipeline: an identical re-registration is a no-op that preserves all outputs; any real change erases the expression's own output, then invalidates from the earliest downstream block that consumes any affected output name (old outputs plus new outputs colliding with downstream inputs), warning about the consumers. Unrelated downstream blocks and consumers shielded by a later same-name producer are left untouched.
Returns

The created ExpressionRegistration, or None when the registration is rejected.

Example
pipeline.define_expression_runtime("import math")
block.register_expression("doubled = seed * 2", save_to_disk=True)

Persisted output pointers

Expression blocks, function blocks, and atom pipelines may replace a same-named upstream output with a pointer to their own committed output. Addresses use globally unique pipeline names and immediate public node names; ordinary pipeline containers, atom implementation blocks, constants, configuration fields, missing outputs, detached roots, and downstream targets are rejected. Nodes in the same integer priority group are alternatives rather than strictly ordered stages, so they cannot point to each other.

Public reads and function/expression inputs follow the chain recursively and return the terminal object or loaded disk artifact, never the pointer. A chain such as A → B → C therefore retains the real completed value at C while A and B contain small pointers, reducing retained memory and duplicate disk generations during complete experimental runs.

Invalidation splices surviving links around removed intermediate pointers, then promotes a removed terminal value to the latest surviving upstream pointer slot without copying the in-memory object. Disk-backed promotion moves the managed artifact to the surviving owner. forbid_invalidate_objects() additionally preserves unrelated cached outputs instead of cascading through them. A partial rerun can temporarily represent more than one generation; rerunning the complete missing suffix converges the chain again. Failed pointer commits restore the prior pointer graph and delete any newly produced disk artifact.

Pointer declarations and active runtime links are preserved by save_pipeline() and load_pipeline(). Missing destinations and cycles are rejected during loading.

pipeline_resolving()

Inject temporary investigation-function inputs from visible pipeline state without registering a node or retaining the resolved values.

mlpipelineholder.pipeline_resolving( pipeline: Any, *, compute: bool = False, mapping: Mapping[str, str] | None = None ) -> Callable

The wrapper binds each call first, so explicit positional or keyword arguments are never replaced. Parameters with Python defaults also keep those defaults. Only remaining required parameters are resolved with the same rules used for registered pipeline functions: produced outputs, pipeline constants, and visible configuration; a root pipeline additionally falls back to object storage. Resolution failures from a higher-priority source propagate rather than falling through to another source.

Parameters
  • pipeline: pipeline whose visible state supplies missing required parameters.
  • compute: when True, compute auto-resolved Dask DataFrame and Series values before calling the function. Explicit caller arguments are not computed.
  • mapping: optional function-parameter to pipeline-variable aliases.
Returns

A decorator that wraps a function, resolving its missing required inputs per call.

Inspect several values temporarily
from mlpipelineholder import pipeline_resolving

@pipeline_resolving(dr_pipeline, compute=True)
def investigate(selected_df, common_df, splitting_date, stock_universe):
    print(selected_df.groupby("ticker").size())
    print(common_df.head())
    print(splitting_date)
    print(stock_universe)

# common_df is supplied explicitly; only the other required inputs are resolved.
investigate(common_df=common_df)

The decorator performs resolution on every call, does not add a pipeline node, and does not cache values loaded only for an investigation. Dask computation results remain local to the call and can be released after the function returns. For ad hoc inspection without defining a function, use PipelineHolder.inspect().
